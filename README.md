# 视频片尾黑场批量裁剪工具

批量检测视频结尾的黑场 / 闪白 / 淡出转场，从转场起点精确裁掉，导出干净成片。原片不动，支持多线程、显卡编码、片头黑场、断点续跑。

面向批量剪辑场景：一整集素材的尾巴都挂着几秒到几分钟的黑屏、渐黑或闪白转场，手动一个个剪太慢，而这个工具可以一次处理完整个文件夹。

## 特性

- **只裁延续到片尾的色场**，中间的黑场/闪白转场不会误删
- **黑场 + 闪白都支持**：`--flash black|white|both`，白场用 `negate` 反相后复用同一套判定
- **宽扫 + 严格复核两层判定**：先把暗剧情画面（或过曝画面）和真色场分开，再确认起点
- **能识别渐变**：亮度逐步下降到黑的淡出、逐步上升到白的闪白，都能从起点裁掉
- **能抓短闪**：片尾几段 0.2~1 秒的闪黑/闪白会被连成一段一起裁
- **能处理超长色场**：黑场长达数分钟时自动全片重扫，定位真正的起点
- **尾帧亮度初筛**：结尾很亮（黑场）或很暗（白场）的文件直接跳过扫描，明显更快
- **显卡加速编码**：有 NVIDIA NVENC 就自动用显卡导出，比 CPU 快约 2 倍
- **片头黑场**：可选，用更严的阈值避免把夜景片头当成黑场
- **断点续跑**：中途失败/中断的文件，可以只重跑这几个
- **中英双语输出**：`--lang en` 一条参数切换成英文，bat 里也能选，详见 [语言](#语言--language)
- **只有一个入口**：根目录就一个 `01_开始裁剪_双击这里.bat`，其余工具收在 `tools\`，下载后不用猜该点哪个
- **不修改原片**，输出到独立的 `<文件夹名>_no_black`，并生成 CSV 记录表

## 依赖

- Python 3.8+（**Windows 发布包已内置 3.13 便携版**，免安装；自己跑源码才需要），只用到标准库，无需 `pip install`
- **ffmpeg / ffprobe**：不用提前装。第一次运行时如果没找到，脚本会问一句「自动下载？」，回车就会下到工具目录的 `bin\` 里（约 120MB，只下一次），之后一直复用。也可以自己装好放进 `PATH`，脚本会优先用自带的 `bin\`，其次才是 `PATH`。
- 可选：NVIDIA 显卡 + 较新的 ffmpeg（使用 `h264_nvenc` 加速导出）

> 为什么东西不直接打进压缩包：两个 exe 加起来 430MB 以上，压完还是上百 MB，GitHub 单文件上限 100MB 过不去，下载体验也差。按需下载一次更划算。

## 快速开始

> **下载完不知道点哪个？就点 `01_开始裁剪_双击这里.bat`。** 根目录只有这一个 bat 是入口，其它工具都收在 `tools\` 里，用不到可以完全不管。

> 发布包里已经带了便携 Python（`runtime\python`，解压即用）和按需下载的 ffmpeg，**下载解压就能跑，不用装任何环境**。第一次运行时它只会问你一句「要下 ffmpeg 吗」，回车即可。

### Windows 图形化入口（推荐）

双击 `01_开始裁剪_双击这里.bat`，把素材文件夹拖进窗口，回车确认，按提示填参数（全部直接回车即用默认值）。处理完可以继续拖下一个文件夹。

窗口一打开就会显示工具名、作者、B站主页和仓库地址，再往下才是「拖入文件夹」的提示——先看清这是什么工具，再决定要不要跑。

首次填好的参数会存进 `trim_config.ini`，下次运行只问一句「直接沿用上次配置？」，回车即可。

### 目录里都有什么

```
01_开始裁剪_双击这里.bat     ← 唯一入口：扫描 + 裁剪一步到位
trim_black_tail.py           核心脚本（bat 会自己找 Python 调它）
tools\
  只扫描清单.bat             先看清单不出片，生成 tail_report.csv
  固定裁末尾N秒.bat          不做检测，直接砍掉末尾 N 秒
  只重跑失败.bat             断点续跑：只重跑上次失败/中断的
```

早期版本根目录平铺了四个 bat，下载后分不清该点哪个，所以现在收成一个入口 + 三个工具。`tools\` 里的三个脚本靠 `..` 反查核心脚本和配置，**不要单独移出去**（复制整个文件夹没问题）。

### 命令行

```bash
# 检测片尾黑场并裁剪，输出到 D:\成片
python trim_black_tail.py -i D:\素材 -o D:\成片

# 只看清单不实际导出
python trim_black_tail.py -i D:\素材 -o D:\成片 --dry-run --report report.csv

# 不检测，固定裁掉末尾 3 秒
python trim_black_tail.py -i D:\素材 --tail 3

# 同时裁掉片头黑场、8 线程、递归子目录
python trim_black_tail.py -i D:\素材 --head --workers 8 --recursive

# 片尾闪白 / 白场转场（-o 默认仍叫 _no_black）
python trim_black_tail.py -i D:\素材 --flash white

# 黑场和闪白都检测，取更早的起点
python trim_black_tail.py -i D:\素材 --flash both

# 只处理指定文件
python trim_black_tail.py -i D:\素材 --only "118,128,143"

# 只重跑上次报告里失败/中断的
python trim_black_tail.py -i D:\素材 --retry-failed report.csv
```

## 语言 / Language

控制台输出、`--help` 帮助文本、错误提示都支持中英两种，默认中文。

| 方式 | 写法 |
|---|---|
| 命令行参数 | `python trim_black_tail.py -i D:\素材 --lang en` |
| 环境变量 | `set TRIM_LANG=en`（bat 内部就是这么传的） |
| bat 图形入口 | 首次设置参数时会问「输出语言？（zh=中文 / en=English）」，选完存进 `trim_config.ini`，之后一直沿用 |

优先级：`--lang` > `TRIM_LANG` > `zh`。

两点说明：

- **报告 CSV 的列名和状态值始终是中文**（`完成` / `跳过` / `失败` 等）。断点续跑和结尾汇总靠这些字面值匹配，翻译会让 `--retry-failed` 失效，所以只翻译人看的输出，不动数据。
- bat 窗口里的提示是**中英并排**一行显示（如 `只扫描末尾多少秒 / seconds to scan from the end?`），不跟随语言切换——这样两种用户都不用猜，也不容易因为分支判断写错而坏掉。

## 工作原理

### 1. 尾帧初筛（可选，默认开）

取视频最后一帧的亮度（YAVG）。超过 `--prefilter-luma`（默认 45）就说明结尾画面还很亮，不可能有黑场，直接跳过后续扫描。这一步每个文件约 0.16 秒。

### 2. 宽阈值扫描

用 `blackframe=amount=90:threshold=96` 在末尾 `--scan-tail`（默认 30 秒）范围内找出所有暗帧时间点，取「一直延续到片尾」的那一段作为候选黑场。

### 3. 严格黑帧复核

宽阈值会把偏暗的剧情画面也标成暗帧，所以候选起点附近再用 `threshold=64、90%` 像素低于阈值复扫一遍，只保留接近纯黑的真黑帧：

- 允许 `--flash-gap`（默认 0.5 秒）以内的间隔，把多段闪黑连成一段
- 最短连续黑帧降到 `--core-min-black`（默认 0.15 秒），能抓到直接切黑
- 如果候选点到严格黑帧之间是「一路渐暗」，保留原起点，避免渐变少裁

### 4. 亮度曲线校验

取黑场起点前后的一段亮度曲线（起点前 1 秒、起点后 2 秒，二分加密采样），确认是渐变淡出还是画面本身偏暗。这一步同时记录末帧亮度、降幅、台阶数等信息，写进报告便于复核。

> 严格黑帧确认通过后，曲线只用于记录，不再否决裁剪——这样直接切黑、黑底带字幕的黑场都能正常处理。

### 闪白 / 白场转场

原理完全对称，不用另写一套判定：先用 ffmpeg 的 `negate` 把画面反相，白场就变成了黑场，直接复用上面的扫描、严格复核和曲线校验。

反相后阈值语义自动对称——「原亮度 > 255-T」等价于「反相后 < T」，所以同一个 `--core-threshold 64` 在黑场和白场下是同等的严格程度（黑场是纯黑 <64，白场是纯白 >191，且都要求 90% 像素达标）。

三个模式：

| `--flash` | 行为 |
|---|---|
| `black`（默认） | 只测片尾黑场 |
| `white` | 只测片尾闪白 / 白场 |
| `both` | 两种都测，都检出时取更早的起点 |

尾帧初筛同样对称：黑场看末帧够不够亮，白场看末帧够不够白（按 `255-v` 折算），所以一个 `--prefilter-luma 45` 同时适配两种极性。

### 5. 异常与复核

- **异常重扫**：检出的黑场时长接近扫描窗口（默认 ≥80%）时，说明黑场可能比窗口更长，自动改为全片重扫
- **标记复核**：裁剪量超过窗口一半（默认 >50%）时打标记，结尾汇总提醒人工看一眼
- **偏暗待确认**：曲线校验发现结尾本身就是暗画面而非黑场时，不裁剪并单独列出

## 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-i, --input` | 必填 | 输入视频文件或目录 |
| `-o, --output` | `<输入>_no_black` | 输出目录 |
| `--mode` | `auto` | `auto` 检测黑场，`fixed` 固定裁末尾 |
| `--seconds` | — | `fixed` 模式裁掉的秒数 |
| `--tail` | — | 等价于 `--mode fixed --seconds N` |
| `--scan-tail` | 30 | 只扫末尾 N 秒，0=全片扫描 |
| `--flash` | `black` | 检测哪种色场：`black` 黑场 / `white` 闪白 / `both` 都测 |
| `--core-threshold` | 64 | 严格色场阈值，越小越严（黑场<64，白场>191） |
| `--core-min-black` | 0.15 | 严格黑帧最短连续秒数 |
| `--flash-gap` | 0.5 | 闪黑分段之间允许的间隔 |
| `--prefilter-luma` | 45 | 末帧亮度高于此值跳过扫描，0=关闭 |
| `--head` | 关 | 同时检测并裁掉片头黑场 |
| `--head-threshold` | 32 | 片头严格黑帧阈值（比片尾更严） |
| `--dark-luma` | 30 | 曲线校验的亮度阈值，0=关闭校验 |
| `--encoder` | `auto` | `auto` / `libx264` / `h264_nvenc` / `hevc_nvenc` |
| `--crf` | 18 | x264 质量，越小越好 |
| `--hw-cq` | 22 | NVENC 质量，越小越清晰越大 |
| `--copy` | 关 | 不重编码直接流复制，最快但裁切点会偏到关键帧 |
| `--workers` | 4 | 并发线程数 |
| `--dry-run` | 关 | 只列清单不实际导出 |
| `--skip-undetected` | 关 | 未检出黑场的文件不复制到输出 |
| `--lang` | `zh` | 输出语言：`zh` 中文 / `en` 英文 |
| `--report` | — | 结果写成 CSV |
| `--ffmpeg-dir` | — | 指定 ffmpeg / ffprobe 所在目录（默认先找本工具 `bin\`，再找 `PATH`） |
| `--no-download` | 关 | 缺 ffmpeg 时不联网下载，直接报错（脚本 / CI 用） |
| `--install-ffmpeg` | 关 | 只下载安装 ffmpeg 到 `bin\` 然后退出，不处理视频 |

完整参数见 `python trim_black_tail.py --help`。

## 报告字段

```text
文件 / 原时长(s) / 模式 / 类型 / 片头去掉(s) / 黑场起点(s) / 裁切点(s) / 去掉(s)
    / 末帧亮度 / 状态 / 输出 / 异常重扫 / 标记复核 / 说明
```

`类型` 列写的是这次裁掉的是「黑场」还是「白场」。

`说明` 列会写明判定依据，例如「严格黑帧起点 24.800s，连续 1.35s」「尾帧初筛：亮度 126 > 45，跳过黑帧扫描」，便于回头核对阈值是否合适。

## 调参建议

| 现象 | 调整 |
|---|---|
| 偏暗画面被误判成黑场 | 调小 `--core-threshold`（如 56、48） |
| 真黑场没检出来 | 调大 `--core-threshold`（如 72、80） |
| 闪黑分了好几段，只裁了最后一段 | 调大 `--flash-gap` |
| 直接切黑（0.1~0.2 秒）抓不到 | 调小 `--core-min-black` |
| 渐变淡出裁少了 | 调小 `--curve-min-drop` |
| 闪白/白场没检出来 | 加 `--flash white` 或 `--flash both` |
| 白场当成画面误检 | 调小 `--core-threshold`（如 56、48），白场要求更纯的白 |
| 扫描太慢 | 调小 `--scan-tail`，或调大 `--prefilter-luma`（如 50） |

## 停止与中断

- 在脚本同目录新建 `STOP.txt`，程序会在当前文件处理完后停下，已完成的结果保留
- 直接关闭 cmd 窗口会触发清理，终止所有 ffmpeg 子进程
- 中断后想续跑：双击 `tools\只重跑失败.bat` 拖入同一个文件夹，或命令行 `--retry-failed 报告.csv`
  续跑时记录表不会被覆盖成只剩重跑的几行，之前的状态原样保留、同名行更新

## 注意

- 原片始终不会被修改，输出文件默认不覆盖已存在的结果（需要覆盖加 `--overwrite`）
- `--copy` 模式因为要在关键帧切，裁切点可能有零点几秒误差，黑场可能残留一点
- GPU 只加速最终导出编码；黑帧扫描和亮度检测走 CPU，因为 ffmpeg 的 `blackframe` / `signalstats` 滤镜只有 CPU 版
- `--recursive` 递归时会保留相对子目录结构，同名文件不会互相覆盖
